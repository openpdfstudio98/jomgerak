# JomGerak audit — 1 November 2026

**Decision: suitable for further beta development; not yet ready for Google Play or Apple App Store, and not equivalent to Google Maps.**

Baseline: `main` commit `251483ed950e0868e80e4bf115866684393fb950`. This audit covers every repository JavaScript file, the HTML entry point, API handlers, service worker, manifest and database schema. Results distinguish code inspection from simulated execution. No production credentials, provider dashboards or real phone GPS sessions were tested.

## Confirmed defects repaired in this branch

| Original issue | Repair / evidence |
| --- | --- |
| A translation MutationObserver rewrites the premium heading on every pass, triggering another pass indefinitely | Only change the heading when its value changes; regression verifies convergence. This can starve UI work when the heading exists. |
| Reset during an in-flight route leaves Find Route disabled | Explicit loading reset on invalidation and stop; regression delays and then resolves the old request. |
| A destination changed while the first request is pending can reuse stale routing state | Invalidate route requests for every selection and text edit; old response cannot restore a route. |
| Text edits leave the previous selected coordinates active | Editing now clears that endpoint and its route; the user must select a new result. |
| Clearing an input can leave queued suggestions active | Cancel its timer, controller and generation; origin/destination timers are independent. |
| Public Nominatim is used for autocomplete | Search now runs on Enter or the visible Search location button. Voice search remains explicit. Shared client helper adds cancellation, timeouts, five-minute caching and sequential spacing. See production restrictions below. |
| Nearby searches only OSM nodes, missing buildings/areas | Search nodes, ways and relations; read center coordinates, filter invalid coordinates and sort valid results by distance. |
| Nearby HTTP error never reaches fallback; old request can repopulate cleared pins | Check HTTP status, use fallback, timeout and invalidate stale results on clear/new search. |
| Multi-stop instructions and live HUD read only the first leg | Read all route legs and label intermediate arrivals as waypoints. |
| Auto-reroute on multi-stop silently removes the intermediate stops | Guard this case and request a stopped/manual recalculation. Preserving only unvisited waypoints remains future work. |
| Navigation can skip the upcoming turn because the closest maneuver point is treated as the current step | Identify the closest step road segment before choosing the next maneuver; simulated approaching-turn regression. |
| Sparse route vertices make remaining distance jump to zero too early | Project the GPS position onto route segments instead of choosing a nearest vertex. |
| Late reroute/multi-stop/walking responses restore invalid state | Shared request generation; stopping navigation also invalidates pending work. |
| Selecting an alternative changes 2D but leaves a stale 3D route | Synchronize the 3D route on selection and clear. |
| Walking/rail selection still allows the main button to calculate a driving route | Delegate walking to pedestrian routing; rail explicitly reports in-app routing unavailable. Clear old mode route on a mode change. |
| Arrival speech is immediately cancelled by stopping navigation | Stop first, then speak the arrival message. Device audio remains unverified. |
| Local community reports are loaded before Leaflet groups exist | Guard early loading and load reports after groups are created. |
| Valid JSON with the wrong local-storage shape can break reports/saved places | Validate arrays and saved-place records. Theme toggles also tolerate unavailable storage. |

The service-worker cache version is bumped and includes `geocoding.js`. Nothing was merged to main or published by this audit.

## Public geocoding: beta-only boundary

Existing public Nominatim use is retained for explicit low-volume searches. Its [official usage policy](https://operations.osmfoundation.org/policies/nominatim/) prohibits client autocomplete, requires attribution/identification, caching, a switchable service and a maximum of **one request per second across the entire application**. Do not submit confidential/personal data in searches.

This patch removes autocomplete and adds per-tab caching/spacing. **Per-tab spacing is not a global application rate limiter.** Do not launch broadly on this fallback. Deploy a suitable shared proxy with durable aggregate rate limiting/cache or an approved production geocoder before public scale. Set Vercel `GEOCODING_BASE_URL` to an HTTPS Nominatim-compatible base URL (no embedded secret). `/api/public-config` and `v64.js` load it at runtime. `config.js` can also provide `geocodingBaseUrl`. Any provider-specific secret belongs server-side.

Public OSRM, Overpass, tiles and Valhalla remain external dependencies without a demonstrated production capacity agreement in this repository. This audit does not certify their availability or commercial suitability.

## Google / Apple login next phase

The existing Supabase integration stores community reports only; it does not yet supply user authentication or owned saved places. Extend that existing backend rather than add fake login buttons.

1. Keep guest navigation available. Add real Google and Apple authentication, callback/error/retry handling, session restoration and logout.
2. Configure Supabase Auth providers and exact production callback/redirect URLs. Google needs OAuth client credentials. Apple web OAuth needs the Apple Developer identifiers/signing setup and maintained client-secret rotation. Keep provider secrets in provider/backend configuration, never HTML or Git.
3. Add per-user profiles, saved places and preferences tables with `auth.uid()` ownership and tested RLS. Migrate local favorites only after an explicit user choice; logout must not expose one person's data to another.
4. Implement account deletion and associated-data handling, plus privacy/account screens before store submission.
5. Test first login, denied consent, cancelled OAuth, expired session, logout, reinstall, Google/Apple account switching, hidden Apple email and eventual native deep links.

Official implementation references:
- [Supabase Google sign-in](https://supabase.com/docs/guides/auth/social-sign-in/auth-google)
- [Supabase Apple sign-in](https://supabase.com/docs/guides/auth/social-sign-in/auth-apple)
- [Supabase redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls)

## Order before store work

1. Review this PR and test its preview on a real Android phone and iPhone. Check map startup, explicit search, all Nearby categories, route alternatives, multi-stop instructions, denied GPS permission, reroute, network loss and language changes.
2. Choose/configure production geocoding/routing/tiles. Complete maneuver tracking, remaining-waypoint reroute and traffic behavior against real routes. Verify any displayed speed/toll restrictions with supported data.
3. Build/test Google and Apple login and owned cloud data. Add abuse protection for community reports.
4. Complete accessibility, responsive layout, battery/background GPS and installed-PWA tests. Record actual results rather than marking buttons as functional solely because they exist.
5. Only after these gates, prepare native Android/iOS builds, signing, deep links, permission descriptions, privacy/account policies, device testing and store review. Native packaging and store submission are not performed in this audit.
